# Oracle Database Shopping Cart Design

## Overview

This repository contains the design and implementation of a shopping cart system using Oracle Database, enhanced with Docker for easy deployment and management. The system is structured to handle various aspects of an online shopping platform, including user management, product browsing, order processing, and more.

## Features

- **User Management**: Includes tables for storing user credentials, details, and address information.
- **Product Management**: Detailed information about products and product categories.
- **Order Processing**: Handling customer orders and order details.
- **Shopping Cart Functionality**: Temporary storage for products that users intend to purchase.
- **User Favorites**: Users can mark products as favorites for easy access later.
- **Logging Operations**: Tracking system activities and user interactions.

## Database Schema

The database is designed with the following key tables:
1. **Users**: Stores basic user information.
2. **User Details**: Contains detailed information about users.
3. **Address**: Manages user address details.
4. **Product Categories**: Classifies products into different categories.
5. **Products**: Contains information about products for sale.
6. **Orders**: Records user orders.
7. **Order Details**: Stores details of user orders.
8. **Shopping Cart**: Manages the users' shopping carts.
9. **Product Shopping Cart**: Links products to user shopping carts.
10. **User Favorites**: Allows users to mark favorite products.
11. **Operation Logs**: Logs system operations and user activities.

## Setup and Installation

### Oracle Database in Docker on macOS (Apple Silicon or Intel)

This project uses the community-maintained [`gvenzl/oracle-free`](https://hub.docker.com/r/gvenzl/oracle-free)
image, which ships native `arm64` builds (Oracle Database Free 23.5+), so no
emulation (Rosetta, Colima, `--platform` flags) is needed on Apple Silicon.

1. **Install Docker Desktop**:
   Download and install Docker Desktop from [docker.com](https://www.docker.com/products/docker-desktop/).
2. **Run the Oracle Database container** (via `docker-compose.yml`):
   `APP_USER`/`APP_USER_PASSWORD` create the application schema the project's
   SQL scripts expect to run under — there's no `CREATE USER` in the scripts
   themselves.
   ```bash
   cp .env.example .env   # then edit .env with your own passwords
   docker compose up -d
   ```
3. **Wait for it to be ready**:
   ```bash
   docker logs -f oracle-db
   ```
   Wait for `DATABASE IS READY TO USE!` in the output.
4. **One-time grants and run the SQL scripts**:
   ```bash
   ./setup.sh
   ```
   This applies the one-time SYS grants (`dbms_crypto` for `GET_SHA256_HASH`'s
   password hashing, and the `ORDER_HISTORY_DIR` directory
   `order_history_operation.save_order_history` writes its CSV export to),
   then runs `Structure.sql`, `procedure-function.sql`, `Package.sql`,
   `Population.sql` and `Test.sql` against the container, in that order. It
   reads the connection details from `.env`. Only needed once per database
   volume — rerunning it against an already set-up database will error on
   duplicate objects/data.

   `Triggers.sql` is intentionally skipped — all ID columns in `Structure.sql`
   already use `GENERATED BY DEFAULT ON NULL AS IDENTITY`, and `Triggers.sql`'s
   sequence-based ID generation references sequences that don't exist in this
   repo, so running it would break inserts.
5. **Accessing the Database**:
   Install the [Oracle SQL Developer for VSCode](https://marketplace.visualstudio.com/items?itemName=Oracle.sql-developer)
   extension, then add a new connection with:
   - Host: `localhost`
   - Port: `1521` (or your `ORACLE_PORT` from `.env`, if set)
   - Service name: `FREEPDB1`
   - Username: `ecommerce` (or whatever `APP_USER` you chose)
   - Password: the `APP_USER_PASSWORD` you set above

   You can then open any `.sql` file (e.g. `Package.sql`) and run it directly
   against the container from VS Code.
